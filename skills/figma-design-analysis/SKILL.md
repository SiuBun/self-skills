# Figma 设计稿解析

将 Figma 设计稿转化为可交接给实现阶段的、可核实的规格。此 skill 只负责读取、解释和整理设计证据，不修改应用代码、资源或 Figma 文件。

## 使用边界

- 适用于用户提供 Figma 链接并要求解析页面、组件、视觉规格、素材或交互关系时。
- 用户同时要求实现 Android UI 时，先完成本 skill 的解析，再使用 `figma-android-ui-reconstruction` 将已核实的规格映射到工程；后者负责代码、资源、系统栏和构建验证。
- 不根据节点名称、相似页面或记忆猜测属性；不能取得完整设计范围时，说明缺口并要求提供正确的 Figma 节点链接。
- 仅分析用户指定节点及直接相关的可见子节点。不要把解析结果当作修改未指定区域的理由。

## 解析流程

1. 从 Figma URL 提取文件 key 和节点 ID。调用 Figma 工具前，先读取其 `use_figma` 指引（如果可用）。
2. 先读取元数据，确认链接目标是否是完整的 Frame 或 Component。链接指向图标、Vector、背景块或叶子文本时，向上定位所属 Frame；无法确认完整范围则停止并要求用户重新提供节点链接。
3. 获取目标节点的设计上下文和截图，同时读取可见的直接子节点。以真实属性和截图为准，节点名称只作定位线索。
4. 对每个需要实现的元素提取并交叉核实：
   - 层级、坐标、宽高、可见性、裁切、滚动和重叠顺序；
   - 填充、描边、透明度、渐变色标与方向、圆角、阴影、模糊和混合模式；
   - 文本的实际字符、字体、字重、字号、行高、字距、对齐、颜色和装饰；混合样式必须按文本片段记录；
   - 图片、图标、Vector、蒙版及其导出需求、显示尺寸和适配方式；
   - Auto Layout、约束、组件实例、变体、设计变量以及可见的状态差异；
   - 按钮、输入、Tab、开关等交互控件的命名、状态和相互关系。
5. 用截图验证图层关系和视觉结果。设计上下文、节点名称与截图不一致时，记录不一致并以实际属性和截图为准。
6. 对尺寸和间距使用节点坐标推导，记录确定值与目测值的区别。不要将系统状态栏、导航栏或 Figma Bottom Bar 混入页面内容间距。

## 素材入口判定

解析素材时必须区分 Figma 工具返回的不同入口，不能看到 PNG URL 就默认它是可直接使用的透明素材：

- `rawImages` 是设计中上传的原始位图。图片填充需要原始透明 PNG 时，优先确认这里是否存在对应资源。
- `svgAssets` 是可独立导出的矢量图层。它用于确认素材边界和矢量来源；是否转换或落盘由实现 skill 和用户要求决定。
- `export` 是节点渲染结果，可能把祖先 Frame、页面背景或 backdrop 一起扁平化。即使节点本身透明，也不能在未验证时将 `export.png` 标记为透明素材。
- `get_screenshot(contentsOnly=true)` 可取得节点隔离渲染的 PNG，适合用户明确需要透明 PNG 的场景；`maxDimension` 只限制最大尺寸，不会把原始 1× 节点放大为 2×、3× 或 4×。
- 素材清单必须记录来源类型、原始尺寸、期望格式、是否需要透明背景，以及 Figma 当前是否直接提供目标倍率。工具无法同时满足透明和倍率时，要在交接中明确说明，不能假定实现阶段会自行抠图或缩放。

## 输出规格

分析完成后，按以下结构简明输出，不创建额外的规格文件，除非用户明确要求：

1. **范围与证据**：文件 key、节点 ID、已确认的 Frame、截图/上下文覆盖范围，以及任何无法确认的部分。
2. **布局结构**：从根容器到主要子区域的层级、尺寸、相对位置、padding、gap、裁切与层级关系。
3. **视觉令牌**：精确颜色、渐变、描边、圆角、阴影、透明度和字体属性；标注其所属元素。
4. **文本清单**：实际文案和分段样式，不以节点名称代替文本内容。
5. **素材清单**：可复用组件、图片/图标/Vector、来源入口、原始尺寸、导出格式、透明要求与目标尺寸；区分静态装饰和运行时动态内容。
6. **交互与状态**：可见的点击目标、选中/禁用/加载等状态和组件变体；未在设计中证实的交互必须标为未知。
7. **实现交接**：列出应交由 `figma-android-ui-reconstruction` 处理的部分，以及会影响还原正确性的风险，例如缺失状态、响应式规则或不完整的节点范围。

## 解析原则

- 设计工具明确给出的属性与通过截图估计的结论必须分开标注。
- 图片被异形容器显示时，先分别确认图片自身和外层框架/蒙版的变换；不要因为容器倾斜就推断图片像素应旋转。
- 重叠装饰、渐变边框和阴影可能是独立图层。只有通过节点层级、填充、描边或截图确认后，才判断其实现结构。
- Figma 的 Bottom Bar、高亮区域或设备外框不是自动等同于 Android 系统 Insets；只记录设计事实，Android 适配由还原 skill 和目标工程处理。
- 不以预览器显示的黑色或棋盘格判断 PNG 是否透明，也不以“包含 Alpha 通道”等同于“实际存在透明像素”。需要交接透明素材时，要求实现阶段验证角落像素和 Alpha 范围。
- 不下载、替换或删除工程资源；如设计中有需要导出的素材，只在输出清单中精确描述，交由实现阶段按工程规范处理。

## 维护此技能

仅加入可重复、且会改变后续设计解析判断的经验。Android 工程专属的实现策略、资源命名、Window Insets 处理和构建命令应保留在 `figma-android-ui-reconstruction`，避免职责交叉。
